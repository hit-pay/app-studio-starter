## Configuration

The navigation structure is serializable JSON. Icons are referenced by name and resolved separately through the `icons` map.

```tsx
import { Sidebar } from '@/components/navigation/sidebar'

const groups = [
  {
    id: 'commerce',
    items: [
      { id: 'orders', label: 'Orders', icon: 'orders', href: '/orders' },
      {
        id: 'products',
        label: 'Products',
        icon: 'products',
        childrenMode: 'inline',
        items: [
          { id: 'all-products', label: 'All products', href: '/products' },
          { id: 'inventory', label: 'Inventory', href: '/inventory' },
        ],
      },
    ],
  },
  {
    id: 'others',
    label: 'Others',
    items: [
      {
        id: 'settings',
        label: 'Settings',
        icon: 'settings',
        childrenMode: 'sub-sidebar',
        items: [
          { id: 'general', label: 'General', href: '/settings/general' },
        ],
      },
    ],
  },
]

const icons = {
  orders: ClipboardRegular,
  products: ShoppingBag1Regular,
  settings: Settings1Regular,
}

<Sidebar
  header="Commerce"
  groups={groups}
  icons={icons}
  activeItem="products"
  activeSubItem="inventory"
  onItemChange={(id, item) => selectItem(id)}
  onSubItemChange={(id, item, parent) => selectSubItem(id)}
  footer={<MyCustomAccountSwitcher />}
/>
```

Items containing nested `items` support two presentation modes:

- `childrenMode: 'inline'` expands children below the parent like an accordion.
- `childrenMode: 'sub-sidebar'` replaces the main navigation with `SubSidebar`. Its back button calls `onSubSidebarClose`.

The default is `sub-sidebar` for backward compatibility. The `footer` accepts custom application content and does not impose an account-switcher component.
