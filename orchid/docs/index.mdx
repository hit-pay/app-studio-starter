Orchid is an open-code component collection for application and business
interfaces. You install its source into your project and retain full
ownership of the resulting code — the shadcn CLI is the installer, there is
no separate Orchid CLI.

It combines UI primitives with higher-level components for forms, data
tables, page layouts, sidebars, confirmations, and common business
workflows. UI primitives install under `src/components/ui` and import from
`@ui/<name>`. Blocks install under `src/components/{category}` and import
from `@/components/{category}/<name>`. Categories match the catalog groups
(actions, displaying-data, feedback, form, layout, navigation, overlays,
utils).

## components.json reference

`components.json` tells the shadcn CLI where to write source files, which
stylesheet contains Tailwind, and how to resolve the Orchid registry. Keep
the compatible values `shadcn init` generated, then verify these settings:

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "base-nova",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/styles.css",
    "baseColor": "neutral",
    "cssVariables": true,
    "prefix": ""
  },
  "aliases": {
    "components": "@/components",
    "utils": "@/lib/utils",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks"
  },
  "registries": {
    "@orchid": "https://orchid-ui-hitpay.vercel.app/r/{name}.json"
  }
}
```

Use the actual global stylesheet path generated by your framework if it
differs from `src/styles.css`. Ensure `@/*` resolves to your source
directory and add a TypeScript path `@ui/*` → `src/components/ui/*`. Orchid
uses `ui`, `components`, `utils`, `lib`, and `hooks`.

Registry `target` uses shadcn placeholders, not import paths —
`@ui/button.tsx` → `src/components/ui/button.tsx`,
`@components/form/form-builder.tsx` → `src/components/form/form-builder.tsx`.
Do not use `@/ui/…` as a target: the CLI treats `@/` as a folder and writes
`src/@/…`. Code imports stay `@ui/…` and `@/components/…`. Do not manually
choose a destination when adding an item — the registry target and your
aliases determine it consistently.

## Theming

Variables use the `--oc-*` prefix, such as `--oc-background` and
`--oc-primary`. Tailwind mappings expose classes such as `bg-oc-background`,
`text-oc-foreground`, and `border-oc-border`.

Customize values under `:root` for the light theme; `.dark` holds the dark
theme values:

```css
:root {
  --oc-primary: #2465de;
}

.dark {
  --oc-primary: #ecece4;
}
```

Apply the `dark` class to an ancestor — normally the document element — to
activate dark mode. Keep the variable names and `@theme` mappings intact so
installed components keep resolving their utility classes. If your build
does not allow remote CSS imports, copy
[orchid-tokens.css](https://orchid-ui-hitpay.vercel.app/orchid-tokens.css)
into the project and import the local file instead of the remote URL — don't
do both, which would duplicate the definitions.

## MCP

Orchid publishes an MCP (Model Context Protocol) server so any AI coding
tool can look up components and their exact props/examples before writing
code, instead of guessing from training data.

```text
https://orchid-ui-hitpay.vercel.app/api/mcp
```

Remote, streamable-HTTP — no install, no local process. Point your tool's
MCP client at this URL.

- `get_orchid_setup` — the Setup steps above, as structured tool output.
  Call this first in a project that isn't configured yet.
- `list_orchid_components` — search or list components (name, title,
  description, category, install command). Filter by `search`, `category`
  (`ui` | `components`), or an exact `name`.
- `get_orchid_component` — full docs for one or more components: props,
  examples, related components, and install command. Pass `name` for one
  slug or `names` for several in a single call.

### Claude Code

```bash
claude mcp add --transport http orchid-ui https://orchid-ui-hitpay.vercel.app/api/mcp
```

Or add it directly to a project's `.mcp.json`:

```json
{
  "mcpServers": {
    "orchid-ui": {
      "type": "http",
      "url": "https://orchid-ui-hitpay.vercel.app/api/mcp"
    }
  }
}
```

### Cursor

Add to `.cursor/mcp.json` (project) or `~/.cursor/mcp.json` (global):

```json
{
  "mcpServers": {
    "orchid-ui": {
      "url": "https://orchid-ui-hitpay.vercel.app/api/mcp"
    }
  }
}
```

### Other tools

Most MCP clients that support a remote/HTTP ("streamable HTTP") server type
accept the same shape: a server named `orchid-ui` with `url` set to the
endpoint above. The exact config file location and field names vary by
tool — check your tool's MCP documentation for its remote-server syntax if
the examples above don't apply directly.

## Prompt your agent

Connecting the MCP server only gives your agent the tools — it still needs
to be told to use them.

One-off, in chat:

```text
This project uses Orchid UI. Before building any screen, call
list_orchid_components to find a matching component or block, then
get_orchid_component with its exact slug(s) for props and examples — don't
guess from memory. Install with the command the tool call returns
(npx shadcn@latest add @orchid/<slug> -y --overwrite). Use Orchid's --oc-*
CSS variables (bg-oc-background, text-oc-foreground, ...) instead of
hardcoded colors.
```

As a project rule (`AGENTS.md` / `CLAUDE.md` / `.cursor/rules`), so every
session follows it, not just the one you typed the prompt in:

```md
## UI components (Orchid)

Orchid UI components are installed as open code via the shadcn CLI, with an
MCP server ("orchid-ui") for discovery. Do not open the registry JSON or
guess a component's API from memory.

- If the project isn't set up yet, call `get_orchid_setup` first.
- Before building a screen, call `list_orchid_components` (search by
  keyword) to check for an existing block or component.
- Call `get_orchid_component` with the exact slug(s) for full props/examples
  before writing code that uses it.
- Install with the command the tool call returns:
  `npx shadcn@latest add @orchid/<slug> -y --overwrite`.
- Style with Orchid's `--oc-*` CSS variables / Tailwind utilities
  (`bg-oc-background`, `text-oc-foreground`, ...), not hardcoded colors.
- If the MCP server is unavailable, fall back to
  https://orchid-ui-hitpay.vercel.app/llms.txt.
```

## Guidance for AI agents

Use a component block when one matches the job. Blocks live under
`@/components/{category}` and are the preferred building blocks for
screens. Use base primitives from `@ui/<name>` only when no Orchid block
covers the job; do not recreate a block by composing its internal
primitives.

Before implementing a screen, read the relevant component's docs
(`get_orchid_component`) and verify the installed source for the exact
props and exports — examples here are usage patterns, not a complete
TypeScript API signature. Preserve existing `components.json`, path
aliases, and MCP configuration when adding Orchid.
